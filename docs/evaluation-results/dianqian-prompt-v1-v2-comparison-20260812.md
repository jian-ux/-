# 点签客服 Prompt V1/V2 对比报告

评测时间：2026-08-12  
模型：deepseek-v4-pro  
样本：`docs/examples/dianqian-doc-dialog-evaluation.json`，共 30 条  
执行方式：同一模型、同一知识数据、同一样本顺序，分别显式指定 `promptVersion=v1` 和 `promptVersion=v2`。每条样本均在独立事务中回滚。

## 最终结论

V2 在本次评测集上优于 V1，可以作为灰度候选版本；生产默认暂时继续保持 V1。

V2 没有削弱现有确定性能力：FAQ、结构化问答、价格转人工、显式转人工、安全拦截、权限边界和情绪策略仍由原有代码处理。V2 只影响需要模型根据 RAG 事实归纳答案的场景，并继续保留 `__ANSWER_PARTIAL__`、`__NO_ANSWER__` 协议。

不直接全量切换的原因：30 条样本规模仍偏小，多轮运行也观察到了模型措辞的随机波动。建议扩大样本后再做小流量灰度，而不是仅凭一次满分切换生产默认值。

## 关键差异

`normal-07-sign-reminder` 的知识原文声称“有三种方式”，但正文只明确列出“自动提醒、手动提醒”两类，存在计数冲突。

- V1 复述了“三种方式”，正文仍只列两类，因此产生 1 次禁止短语违规。
- V1 本轮在另一条通知排查回答中漏掉“工作通知”，必要事实命中率为 98.11%。
- V2 未复述冲突总数，完整保留短信、微信公众号、钉钉工作通知、签署链接和二维码，必要事实命中率为 100%，违规数为 0。

人工复核 18 条发生变化的回复后，V2 的主要改善是：

1. 对“能否直接修改”先明确回答“不能直接修改”，再给出撤回、修改、重新发起的替代路径，边界比 V1 清楚。
2. 完整保留期限、数量、阈值和前置条件，例如套餐有效期 1 年、到期清零、50 份阈值和提前 7 天申请。
3. 事实已完整时不再追加无意义追问。
4. 遇到事实总数与明细不一致时，不复述无法核实的总数，只列出明确项目。

## 上线建议

1. 生产默认继续保持 `AI_CUSTOMER_SERVICE_PROMPT_VERSION=v1`。
2. 将 V2 作为候选版本，扩充价格边界、账户安全、模糊多轮、投诉、知识冲突和无答案场景后复测。
3. 扩展集仍满足关键指标零退化后，再做小流量灰度；重点监控无依据断言、必要条件遗漏、错误转人工率和用户追问率。
4. 灰度出现退化时，将配置恢复为 `v1` 并重启服务即可回滚，无需改数据库。
